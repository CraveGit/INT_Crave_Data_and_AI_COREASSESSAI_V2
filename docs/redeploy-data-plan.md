## RESOLVED — cross-container naming (was open)

Unified on namespace `CRA` -> both apps use `CRA_*` tables. AI API `data_initializers.py`
now `pd.read_sql` from `CRA_*` (no CSV in live path). It connects to the CAP HDI

Post-deploy: grant that HANA user SELECT on the CAP container schema; set .env
SCHEMA to the CAP container schema.

## OPEN DECISION — cross-container table naming (blocker for AI API)

The two apps use different table-name prefixes:

- **AI API** queries `{SCHEMA}.KCC_REF_PRICELIST`, `KCC_REF_FIORIAPPS`, `KCC_CONFIG_MSTR`, `KCC_REF_EVENTS`, `KCC_TSHIRT_CONFIG`, `KCC_PRIORITY_CONFIG`  (prefix **`KCC_`**).
- **CAP** (namespace `KCC_prod`) creates **`KCC_PROD_REF_PRICELIST`**, `KCC_PROD_CONFIG_MSTR`, ...  (prefix **`KCC_PROD_`**).

So CAP-seeded data is invisible to the AI API as-is. Pick one:

1. **Point AI API at CAP's container** (recommended, single source of truth):
   - Give AI API a HANA key/creds for the CAP HDI container (or an HDI cross-container grant + synonyms).
   - Set AI API `SCHEMA` to the CAP container schema.
   - Rename its queries `KCC_*` → `KCC_PROD_*` (6 table names in `data_initializers.py`), OR create synonyms `KCC_REF_PRICELIST → KCC_PROD_REF_PRICELIST` in the AI API's access.
   - Then flip the two commented `pd.read_sql` lines (pricelist, fioriapps) back on and delete the last 2 CSVs.

2. **AI API keeps its own schema** (two copies):
   - Seed the same reference data into the AI API's own HANA schema (separate script), keep `KCC_` names.
   - Simpler isolation, but pricelist/fiori data duplicated + can drift.

Until this is decided, AI API keeps reading `pricelist.csv` + `fioriapps.csv` (they stay shipped). No runtime break.

## Deploy sequence (reference)

1. Attach HDI container to CAP app (mta.yaml `coreassess-db`).
2. `npm run build` + `npm run deploy` → db-deployer seeds `db/data/*.csv` automatically.
3. Export remaining old-prod reference tables → add as `db/data/KCC_prod-*.csv` → redeploy.
4. Resolve cross-container decision above; if option 1, flip AI API to `pd.read_sql` and drop last 2 CSVs.
